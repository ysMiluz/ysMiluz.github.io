## 1. 述职摘要

### 1.1 本周期承担的核心任务

本周期围绕 sEMG 手部姿态预测，承担的工作不只是训练单个模型，而是建设一条从原始传感器数据到可评估物理输出的可信研发链路。主要职责可归纳为五类：

1. 整理 FM_PULSE 训练、推理和实验工程，使研究代码可配置、可复现、可交接。
2. 治理 EMG、Manus、Vision、IMU 等异步数据的时间、格式和标签质量问题。
3. 建立统一 Benchmark，保证不同 GT、任务协议、被试和设备结果可以公平比较。
4. 打通 SHM 标准手训练、评估、checkpoint、ONNX 和结构化输出链路。
5. 设计并实现 Vision+sEMG+IMU 三模态双手 Fusion2Pose，比较 Pose-State Query 与 Chord-MulT 两种融合路线。

### 1.2 一句话总结

过去五个月，我将 FM_PULSE 从若干单点算法和实验脚本，推进为覆盖“数据时间正确性、统一训练评测、SHM 标准输出、多模态因果融合”的可复现研究平台；同时对尚不具备正式验收条件的标签、Root 和 Benchmark v2 问题建立了明确边界。

### 1.5 本周期最重要的三个结果

#### 结果一：解决数据时间错位这一模型上限问题

EMG 与 Manus 原本存在 0.7–1.5 s 的系统错配。该问题通常不会导致代码报错，却会让模型学习错误的输入输出关系。本周期完成了跨时钟域、跨日期、字段长度不一致和损坏文件的系统治理，并在约 850 个原始文件上验证。

#### 结果二：建立结果可比较、结论可审计的 Benchmark

通过分离 tracking 与 regression、ergo 与 skeleton GT、普通 test 与跨人/跨设备轴，避免用 GT-seeded tracking 结果替代纯 EMG regression 结果。Benchmark v1.0 regression test MAE 达到 16.54°，并形成统一脚本、split 和聚合规则。

#### 结果三：从零完成三模态双手研究平台

完成 Pose-State Query 和 Chord-MulT 两套网络的输入、encoder、因果 memory/cross-attention、loss、反向、checkpoint、评估和输出全链路，并在约 23.6 小时数据上形成首轮结果。软件闭环已经完成，当前主要瓶颈已从“代码缺失”转移为“完整 SHM23、Root 和 camera-space 标签不足”。

## 4. 核心项目 STAR 复盘

## 4.1 项目一：FM_PULSE 工程重构与 PULSE 多任务模型

### S — Situation：为什么要做

### T — Task：需要达到什么结果

- 建立清晰、可安装、可配置的工程结构。
- 让训练、实时推理、离线推理和实验代码各自职责明确。
- 建立支持 force/pose/gesture 任意组合的多任务模型。
- 支持后续 SSL、LOSO、消融、ONNX 和多人协作。

### A — Action：本人采取的关键行动

1. 将代码归并到 `src/inference`、`src/experimental`、`src/pipeline` 等清晰边界。
2. 将实时推理拆成串口解析、滤波、特征提取、解码、pipeline、实时执行和可视化等模块。
3. 建立 pyproject、extras、CLI 和 Hydra 配置树，减少脚本内硬编码。
4. 将 HTT 统一升级为 PULSE，增加三个任务 head 和任务启停配置。
5. 将单层输出升级为两层 MLP，引入 GELU 和 Dropout。
6. Pose 训练加入 Smooth-L1 和速度一致性约束，多任务使用同方差不确定性自动加权。
7. 增加 TensorBoard、学习率、任务权重和指标日志。
8. 建立 large、SSL+finetune、clean-data、LOSO 和训练曲线工具。
9. 增加 PSD、频段能量、RMS、方差和跨人信号质量分析。

### R — Result：形成了什么结果

- 首轮重构覆盖 55 个文件，新增约 4,467 行。
- 训练、推理、数据和实验形成清晰分层，重复 ONNX 逻辑被收敛。

- 形成单任务、多任务、SSL 和 LOSO 四类实验入口。
- 后续时间对齐、Benchmark、SHM 和 Chord 可以复用同一套工程习惯和配置机制。

### 价值与复盘

该项目的价值不在于某一个模型指标，而在于把一次性脚本转化为持续迭代底座。后续复杂问题能够被拆成数据、模型、训练、推理和评测子问题，降低了定位成本和协作风险。

## 4.2 项目二：EMG–Manus 时间戳对齐

### S — Situation：问题为什么隐蔽且严重

EMG 手环存在硬件缓冲延迟，首个有效样本相对 Manus 通常晚 0.7–1.5 s。旧处理逻辑把两路信号分别归零，因此“EMG 1.1 s 的肌电”会被配到“Manus 0 s 的姿态”。这一错误不会导致程序异常，却会系统性破坏监督信号。

跨日期数据还存在三类额外问题：

- `emg_sys_timestamps` 有时是会话相对时间，有时是系统单调时钟。
- ergonomics 已上采样，但 timestamp 数量仍保留原采样长度。
- discovery 阶段遇到损坏 NPZ 会中断整批任务。

### T — Task：目标

恢复 EMG 与 Manus 的共同物理时间轴，并保证逻辑可以跨被试、跨日期稳定工作；同时建立可批量诊断、可复现、对异常文件有明确处理策略的流程。

### A — Action：根因定位和修复

1. 对 20 个 lcl-0126 文件统计首样本偏移，得到均值 1,224 ms、范围 703–1,531 ms。
2. 不再将两路信号独立归零，而是保留 EMG 的 session offset。
3. 在共享会话时间轴上插值 Manus，仅保留两路真实重叠区间。
4. 根据 timestamp 与 `record_t0` 的关系自适应识别时钟域。
5. 对上采样后长度不一致的数据，按真实总时长重建时间网格。
6. 在 discovery 阶段增加损坏文件捕获、skip reason 和批量诊断报告。
7. 使用多被试、多日期数据回归验证，而非只在单个样例上通过。

### R — Result：量化结果

| 验证项 | 修复前 | 修复后 |
|---|---:|---:|
| lcl-0126 平均错位 | 1,224 ms | 对齐到共同时间轴 |
| wyl-0101 跨天异常 | 11,617,969 ms | 约 1,128 ms 真实硬件延迟 |
| wyl-0101 成功率 | 部分失败 | 185/185 |
| fgw-0917 异常 trial | 83/83 失败 | 83/83 成功 |
| 多被试总体 | 不稳定 | 约 850 个原始 NPZ 跑通；1 个物理损坏文件安全跳过 |

### 价值与复盘

这是本周期最关键的数据治理成果之一。相比继续调整网络容量，先修复标签对应关系更直接地恢复了模型可学习上限，也形成了后续三模态严格因果对齐的工程基础。

## 4.3 项目三：Benchmark v0.1/v1.0 泛化评测

### S — Situation：原有结果为什么不能直接比较

不同实验存在 GT 来源、初始姿态、左右手变换、split 和聚合口径差异。尤其 tracking 使用 GT 初始姿态，而公开 regression 任务不提供 GT seed；如果将两者放在同一表格中直接比较，会得到不公平结论。此外，网络盘 mmap 吞吐低且可能造成 OOM。

### T — Task：需要回答的核心问题

1. ergo 直读角度与 skeleton 解算角度作为 GT 时的差异。
2. 模型在普通 test、跨被试和跨设备上的泛化能力。

## 4.5 项目五：Benchmark v2 Pipeline 与 S3 稳定性治理

5. 使用降低并发、lazy session、`num_workers=0` 和单进程重试逐层隔离问题。

## 4.7 项目七：Chord Fusion2Pose 三模态双手架构

### S — Situation：任务复杂度

目标是从双目视频、双侧 sEMG 和双腕 IMU 预测双手 SHM 姿态。三种模态采样率不同、时间不齐、存在缺帧和缺模态；原始架构图只描述概念，没有完整代码合同、双手监督规则、Root 物理含义、训练评测入口和有效性条件。

### T — Task：需要完成的两条路线

1. Pose-State Query：以上一姿态状态为中心，三路模态提供逐 DoF 证据并更新状态。
2. Chord-MulT：执行六个有向 Cross-Attention，再做三路 temporal memory 和全局融合。

验收范围要求覆盖 raw/video/SHM 配对、encoder、因果对齐、前向、loss、反向、checkpoint、resume、评估、NPZ 和文档。

### A — Action 1：建立双手输入与时间合同

- 固定 bilateral sEMG 为 left16+right16。
- 固定 wrist IMU 为 left9+right9，并保留可选 geometry/head IMU 接口。
- 统一使用 int64 `sync_ts_ns` 作为物理时钟。
- 自动配对 raw、video 和 SHM，记录 skipped reason。
- 使用 subject-level split，避免同一被试跨集合泄漏。
- 对缺失模态采用零值加全 false mask，不把零值当作真实观测。
- 整理 368 个视频、约 23.6 h、约 253 万帧的清洗训练集。

### A — Action 2：实现 encoder 与严格因果对齐

- Vision encoder 支持 Light-CNN、MobileViT 和 Swin。
- sEMG encoder 支持 causal TCN、Production TDS 和 TDS+TCN。
- IMU 使用因果 TCN。
- 所有 Cross-Attention 仅允许 `source_ts <= target_ts` 且位于历史窗口，禁止未来信息泄漏。
- Production TDS 从 2,000 个 raw samples 生成 3 tokens，总 stride 为 80 samples/40 ms，左侧上下文为 1,790 samples/895 ms。

### A — Action 3：实现 Pose-State Query

- 为 Vision、sEMG、IMU 建立三路独立 causal Memory Bank。
- 由上一 SHM23、速度、IMU 和时间间隔形成状态先验 `X⁻(t)`。
- 使用 7 个解剖结构 Pose Query 查询三路 memory。
- 每路生成 23D innovation、gain 和 log variance。
- IMU learned update 仅开放 wrist DoF 21:23，EMG 仅开放 finger DoF 0:21。
- 使用 QGR-PU 做逐 DoF 更新；EMG 缺失时保持 exact fallback。
- 窗口内状态 carry 不 detach，使梯度能够通过时间传播。

### A — Action 4：实现 Chord-MulT

- 实现 IMU→Image、EMG→Image、Image→IMU、EMG→IMU、Image→EMG、IMU→EMG 六条独立有向边。
- 每个目标模态拼接另外两路 context，形成 512D token memory。
- 三路 endpoint 各输出 512D，拼接为 1,536D global feature。
- 通过 LayerNorm 和 Residual MLP 输出双手 Pose52。
- 支持 edge hard ablation 和 branch modality dropout。

### A — Action 5：完善 loss 与物理输出

- Pose-State 使用 center、sequence、heteroscedastic NLL、dynamics、velocity 五项 masked loss。
- Chord 当前使用有效 theta20 的 masked Smooth-L1，避免对缺失 Root6 进行伪监督。
- 实现 SHM23 joint limits、可微 FK、SHM25、Root 和 SO(3) 验证。
- 实现正式 `prediction.npz` 字段，包括 frame、hand side、theta23、valid mask、SHM25、wrist rotation、wrist valid 和 accepted。

### A — Action 6：解决训练吞吐问题

H200 利用率接近 0 的主要原因并非模型计算，而是每个 window 都重开 MP4 并随机 seek H.264。为此：

1. 将 MP4 改为一次顺序解码。
2. 预计算 FP16 Vision Feature Cache，shape 为 `[T, 2, 256]`。
3. 缓存保留 frame validity 和 int64 timestamp。
4. 训练时跳过重复视频解码，sEMG/IMU 继续按物理时间构建因果窗口。

### A — Action 7：代码审计与关键修复

本轮审计修复了以下高风险问题：

- geometry 分支 config 未定义。
- 标签 `searchsorted` 可能选择未来样本。
- 最新无效样本会覆盖更早合法 causal sample。
- 全空 attention row 导致 `SoftmaxBackward` NaN。
- memory padding 和线性层 bias 形成伪 evidence。
- 窗口内 `X(t-1)→X⁻(t)` 未真正闭环。
- Root frame 命名导致 wrist DoF 可能重复施加。
- 缺少 SO(3) 正交和 `det=+1` 验证。
- 未显式 AMP 时 CUDA autocast 仍可能开启。
- 训练结束评估 last 而不是 best checkpoint。
- 多 session NPZ 主键冲突。
- rejected Root NaN 进入 streaming cache。
- 半精度下 int64 纳秒时间差存在溢出风险。

### R — Result 1：软件闭环

- 两套架构均完成 `raw → encoder → memory/attention → head → loss → backward → checkpoint → resume → eval`。
- 输入和输出均支持双手；只有存在真实标签的一侧参与 loss，不以零角冒充另一只手 GT。
- 当前完整测试套件为 92 passed，并完成真实 MP4+NPZ forward/backward smoke。
- 形成模块说明、架构审计、逐层张量推导、流程图、PPT 和协作文档。

### R — Result 2：约 23.6 h 数据首轮结果

| 模型 | Best epoch | Overall MAE | Left MAE | Right MAE |
|---|---:|---:|---:|---:|
| Pose-State Query | 14 | 22.62° | 28.26° | 21.53° |
| Chord-MulT | 16 | 25.40° | 35.20° | 23.51° |

- Pose-State Query 比 Chord-MulT 低 2.78°。
- 关闭 early stopping 后，Pose-State 相比第一轮改善约 1.44°；Chord 未出现新的 best。
- 两个模型都呈现训练 loss 继续下降而 validation 不再改善的过拟合趋势。

### 结果边界

- test 有效角元素左手 960、右手 4,960，Overall 更接近右手表现，不是左右手等权结果。
- 当前主要监督 theta20；theta23 中 index 2 和 wrist 21:23 缺少直接 GT。
- 当前数据缺少可信 camera Root、geometry/head IMU，因此不能报告正式 SHM25 MPJPE。

### 价值与复盘

本项目建立了可比较两种融合思想、可执行模态/encoder/edge/loss 消融、并对物理输出有效性负责的研究平台。软件链路已经闭环；下一阶段真正决定精度上限的是监督完整度、左右手平衡和 Root 标签，而不是继续无条件扩大 encoder 维度。

## 5. 关键问题解决能力

### 5.1 从模型误差反查数据，而不是先扩大模型

本周期多次证明，姿态误差可能来自时间戳、side、GT、mask、split 和 I/O，而非模型容量：

| 表面现象 | 实际根因 | 处理方式 |
|---|---|---|
| 模型训练不收敛 | EMG 与 Manus 秒级错配 | 恢复共同物理时间轴 |
| 右手误差异常 | MIRROR_X 错误翻转 FE 符号 | 修复坐标变换并重建 Benchmark |
| H200 利用率接近 0 | 每个 window 重开 MP4、随机 seek | 顺序解码和 FP16 feature cache |
| Softmax backward NaN | 全空 attention row | 安全 masked softmax 和全空分支处理 |
| 模态缺失仍有输出贡献 | padding 与 bias 形成伪 evidence | value+hard mask 双合同 |
| v2 训练反复退出 | s3fs/FUSE 缓存退化 | 文件头扫描、单进程隔离、Range GET 方案 |
| 指标看起来很好 | tracking 使用 GT seed 或 test 泄漏 | 分离协议并披露结论边界 |

### 5.2 用最小变量控制定位复杂故障

常用方法包括：

- 将多 worker 降为单 worker 或 `num_workers=0`。
- 从完整训练退化为文件头、单样本、单 batch 和 CPU smoke。
- 固定 EMG，仅替换 GT 做强控制 A/B。
- 固定 test，只替换训练标签评估标签价值。
- 分别检查对象源、挂载层、缓存层、DataLoader 和模型数值。
- 对无标签项显式 mask，而不是用零值假装有效监督。

### 5.3 将概念架构落实为精确合同

对 Chord 的实现不止停留在结构图，而是逐层明确：

- 输入 shape、采样率、token 数和 embedding 维度。
- Query/Key/Value 方向和六条有向边。
- 时间戳、历史窗口和 0-lookahead 规则。
- LayerNorm、残差、MLP、gain、uncertainty 和 QGR-PU 更新。
- 双手输出、逐 DoF valid mask 和 loss 路径。
- SHM23、Root6、FK、SHM25 和 camera frame 的物理区别。
- forward、backward、checkpoint、streaming 和 writer 合同。

### 6.2 数据质量

- 使用 int64 纳秒时间戳先做差，再转换为浮点秒，避免 AMP 下绝对时间溢出。
- 对损坏、逆序、未来读取、非有限值、退化旋转和缺失字段进行硬拒绝或明确跳过。
- 使用 subject-level split 和交集检查防止被试泄漏。
- 对失败样本保留 skipped manifest 和 skip reason。
- 不将缺失的另一只手、Root 或 SHM DoF 用零值冒充真值。

### 6.3 实验质量

- 区分 training loss、弧度 MAE、角度 MAE、逐帧和逐 session 指标。
- 区分 tracking 与 regression、正式 test 与阶段性 validation。
- 报告左右手、逐 DoF 和有效元素数量，避免 Overall 掩盖数据不平衡。
- 训练完成后回载 best checkpoint，而不是默认评估 last。
- 对 multi-seed 使用均值和标准差，不以单个 seed 替代稳定性结论。

### 6.4 结论质量

本周期坚持以下原则：

1. 软件闭环不等于物理精度闭环。
2. smoke 通过不等于正式训练完成。
3. validation 中间值不等于 test 结果。
4. masked theta20 不等于完整 theta23。
5. Pose52 root6 不等于 wrist articulation。
6. 缺失 Root 时 `accepted=false` 是正确结果，不应伪造有效输出。

## 10. 不足、反思与改进

### 10.1 Benchmark v2 未形成正式结果

#### 现状

虽然三 seed 均产生阶段性 validation 结果，但未完成 50,000 steps 和 best checkpoint test。

#### 原因

- 训练数据依赖不稳定的 s3fs/FUSE 缓存。
- DataLoader worker 最终收到 SIGTERM。
- 基础设施治理与训练推进并行，实验周期被反复中断。

#### 改进

- 将 S3 Range GET 或稳定本地物化作为正式训练前置条件。
- 先执行全量 header/schema 和真实 batch preflight。
- 使用断点恢复和训练进程监控完成剩余 steps。
- 最终统一报告三 seed best test mean±std。

### 10.2 Chord 当前精度不足且左右手不平衡

#### 现状

Pose-State Query 22.62°、Chord-MulT 25.40°，均未达到可产品化精度；左手有效监督显著少于右手。

#### 原因

- 主要监督 theta20，完整 theta23 不足。
- 左手有效角元素 960，右手 4,960，数据严重不平衡。
- Root、camera-space SHM25 和部分 geometry/head IMU 缺失。
- 两个模型均出现过拟合。

#### 改进

- 先补完整双手 theta23 和逐 DoF valid，再进行模型容量调整。
- 使用左右手平衡采样和等权指标。
- 完成模态、encoder、edge、dynamics、gain 和 uncertainty 消融。
- 对不确定性做 calibration，而不仅作为 loss 参数。

### 10.3 单人高分结果的泛化证据不足

#### 现状

部分单人 test 指标较低，但存在 failed 样本混入、test 过小或 val/test 重叠。

#### 改进

- 重建 passed-only 数据并使用严格不重叠 split。
- 固化 subject/session 级哈希，自动阻止交叉污染。
- 将单人 overfit 指标定位为链路验证，不替代跨人泛化结果。

### 10.4 项目范围较广，正式提交节奏需要加强

#### 现状

本周期同时覆盖数据、模型、基础设施、部署和文档，快速解决了较多问题，但 Chord 部分工作尚未形成清晰提交序列。

#### 改进

- 按 data contract、encoder、fusion、loss、output、tests 拆分 MR。
- 每个 MR 附设计说明、shape contract 和测试证据。
- 建立周级 milestone 和决策记录，降低后续追溯成本。

## 15. 可能的评审问题与回答要点

### Q1：为什么 Chord 的误差比单模态 Benchmark 高？

回答要点：

- 两者数据、标签完整度、任务合同和 split 不同，不能直接横向比较。
- Chord 当前主要监督 theta20，完整 theta23 和 Root 不足。
- 左右手有效监督不平衡，且多模态数据存在缺帧和缺模态。
- 当前结果证明的是两架构在同一 Chord 数据上的相对表现，不代表多模态一定弱于单模态。

### Q2：为什么不继续增大 256D encoder？

回答要点：

- 两个模型都已出现训练 loss 下降、validation 不改善的过拟合。
- 当前主要瓶颈是标签缺失、左右手不平衡和 Root 不可用，而非明确的欠拟合。
- 应先用统一标签和消融证明容量瓶颈，再调整 embedding 维度。

### Q3：Benchmark v2 为什么不能算完成？

回答要点：

- 三 seed 只运行到约 20K steps，目标是 50K。
- 当前只有阶段性 validation，没有 best checkpoint 正式 test。
- 已完成的是训练基础设施、预检和故障定位；正式成绩仍需恢复训练后验收。

### Q4：为什么 Vision A/B 没有直接训练？

回答要点：

- Vision processed 标签路径和 schema 不完整。
- 强配对样本缺少 subject_id，存在 split 泄漏风险。
- 数据还有异常日期、全零和大跳变问题。
- 在这些条件下训练无法回答 Vision 标签是否接近 Manus，因此先完成数据审计更合理。

### Q5：Pose-State Query 为什么优于 Chord-MulT？

回答要点：

- 当前证据只支持“在本数据和训练预算下低 2.78°”。
- 可能原因是 Pose-State 的状态先验、逐 DoF gate 和模态职责约束更适合当前不完整监督。
- Chord 1,536D 全局融合参数更多，在当前数据量和不平衡条件下更容易过拟合。
- 需要三 seed 和机制消融才能形成更强因果结论。

### Q6：软件链路完成为什么还不能输出有效 SHM25？

回答要点：

- SHM25 需要 theta23、标准手骨长和有效 Root/相机坐标变换。
- 当前数据缺少可信 Root 或 camera-space GT。
- FK 可以生成局部骨架，但不能伪造相机坐标中的整手位置和旋转。
- 因此 writer 输出 `accepted=false` 是对物理有效性负责。

### Q7：本周期最有价值的工作是什么？

回答要点：

- 如果从数据基础看，是解决约 0.7–1.5 s 的 EMG–Manus 系统错位。
- 如果从研发效率看，是建立统一 Benchmark 和可复现训练链路。
- 如果从未来能力看，是完成两套三模态双手架构和 SHM 物理输出平台。
- 三者共同作用，把模型研发从“能跑”推进到“结果可信”。

### Q8：下一阶段最需要什么支持？

回答要点：

- P0 是完整双手 theta23、逐 DoF valid、Root/camera-space GT。
- 其次是稳定 S3 或本地高速数据入口，保证三 seed 长训练。
- 还需要 Vision processed 标签、subject 映射和固定版本。
- 有了这些条件，才能完成公平消融和正式物理指标验收。

## 18. 最终总结

本周期的核心成果不是孤立地完成若干模型，而是建立了一条可信的多模态手部姿态研发链路：

```text
原始传感器
  → 时间与质量审计
  → 数据合同与 subject split
  → 单模态/多模态 encoder
  → 严格因果融合与状态更新
  → SHM23 / Root / FK / SHM25
  → masked loss 与稳定反向
  → checkpoint / ONNX / NPZ
  → 统一评测、结果边界与发布条件
```

本周期已经闭环的关键问题包括：工程结构分散、EMG–Manus 秒级错位、GT 和任务协议混比、右手符号错误、大规模 I/O、全空 attention NaN、缺失模态伪证据、双手单侧监督、Root 物理语义混淆和实验不可复现。

尚未完成的关键问题也已经被明确量化：完整双手 SHM23/Root 标签、Benchmark v2 正式三 seed test、Vision processed 标签和 force 标签语义。下一阶段将以这些真实瓶颈为中心，推动现有平台从研究闭环进入正式指标和部署候选阶段。
