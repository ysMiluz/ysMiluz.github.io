## 3.1 项目一：FM_PULSE 工程重构与 PULSE 多任务模型

### S — Situation

早期代码包含训练、实时推理、数据处理和实验原型，但目录分散、重复实现较多、配置入口不统一。实时推理单文件接近千行，模型主要围绕单任务，难以同时验证姿态、力和手势任务，也不利于多人协作和后续部署。

### T — Task

建立清晰、可安装、可配置的 FM_PULSE 工程骨架；同时形成一个可做多任务学习、消融、预训练和 LOSO 泛化评估的 PULSE 模型。

### A — Action

1. 重构项目目录和包边界，统一训练、推理、pipeline 和实验代码位置。
2. 将实时推理按职责拆成 8 个模块，消除 ONNX 推理重复逻辑。
3. 建立 pyproject、extras、CLI、Hydra 配置树和标准包导入。
4. 将 HTT 升级为 PULSE，增加 force/pose/gesture 三 head 与任务开关。
5. 增加 Pose Smooth-L1、速度一致性和多任务不确定性加权。
6. 增加 TensorBoard、LOSO、SSL pretrain、finetune 和多组实验脚本。
7. 建立数据格式、架构原理、FactorizedBlock 和 TDS 时序说明。
8. 增加 EMG 频段质量分析、PSD 清洗和训练曲线可视化。

### R — Result

- 首轮工程重构覆盖 55 个文件，新增约 4,467 行，形成清晰的训练/推理/数据/实验分层。
- PULSE 支持三任务任意组合和自动 loss 平衡，具备单任务、多任务、SSL、LOSO 四类实验入口。
- QST_clean 阶段记录达到总 loss -0.93、pose R² 0.464；该结果是原型阶段训练记录，不作为后续 SHM/Benchmark 正式指标。
- 训练、数据格式和架构决策形成文档，降低了后续模块接入和问题定位成本。

### 业务价值

将一次性研究脚本转化为可持续迭代的工程底座，使后续时间对齐、Benchmark、SHM 和 Chord 工作可以复用同一套配置、训练和推理基础设施。

## 3.2 项目二：EMG–Manus 时间戳对齐

### S — Situation

EMG 手环存在约 0.7–1.5 s 硬件缓冲延迟。旧预处理将 EMG 和 Manus 各自从 0 开始计时，导致实际发生在 1.1 s 左右的 EMG 被错误配对到 Manus 0 s 姿态。跨日期数据还存在不同 timestamp 时钟域、字段长度不一致和损坏文件等问题。

### T — Task

恢复 EMG 和 Manus 的真实共同时间轴，让数据可以跨被试、跨日期稳定进入训练，并建立可批量诊断、可复现的修复流程。

### A — Action

1. 统计 20 个 lcl-0126 文件，量化 EMG 首样本延迟均值 1,224 ms、范围 703–1,531 ms。
2. 保留 EMG 真实 session offset，在共享会话时间轴上插值 Manus，并仅保留两流重叠区间。
3. 实现自适应时钟域判断：当 emg_sys_timestamps 与 record_t0 同源时减去 record_t0，否则保留已有相对时间。
4. 对已上采样 ergonomics 与原速 timestamp 长度不匹配的文件，按真实总时长重建时间网格。
5. 对损坏 NPZ 增加 discovery 级 try/except 和明确 skip reason。
6. 增加 diagnose 模式、批量延迟统计和独立修复脚本。

### R — Result

| 验证项 | 修复前 | 修复后 |
|---|---:|---:|
| lcl-0126 平均错位 | 1,224 ms | 0 ms 共同轴 |
| wyl-0101 跨天平均异常 | 11,617,969 ms | 1,128 ms 真实硬件延迟 |
| wyl-0101 成功率 | 部分失败 | 185/185 |
| fgw-0917 异常 trial | 83/83 失败 | 83/83 成功 |
| 多被试总体 | 不稳定 | 约 850 个原始 NPZ 跑通；1 个物理损坏文件被安全跳过 |

### 业务价值

避免模型学习“错误时间配对”的 EMG→姿态关系。这类错误不会一定导致程序报错，却会直接压低模型上限；因此该工作解决的是训练数据可信度的根问题。

## 3.3 项目三：Benchmark v0.1/v1.0 泛化评测

### S — Situation

不同实验使用的 GT 来源、初始姿态、左右手处理和聚合口径不一致。tracking 依赖 GT 初始姿态，而公开榜单是纯 EMG regression；如果直接比较，会得到看似更好但不公平的结论。网络盘 mmap 还造成吞吐和 OOM 风险。

### T — Task

建立可复现、无口径混淆的 vEMG2Pose Benchmark，回答：

1. ergo 直读 GT 与 skeleton 解算 GT 对训练效果有何差异；
2. 模型在普通 test、跨被试、跨设备上的泛化表现；
3. tracking 与 regression 应如何分别报告；
4. 大规模数据如何稳定加载和评估。

### A — Action

1. 构造 ergo-vs-skeleton 强控制 A/B：EMG 完全一致，仅 joint_angles GT 不同。
2. 建立 FE-RMSE 对齐门和 skeleton GT 解算。
3. 修复右手 MIRROR_X 错误翻转 FE 符号的问题。
4. 构建 train/val/test、左右手、subject/device axis split。
5. 建立逐 frame、逐 sample、逐 session 和逐 subject 汇总。
6. 为 regression 单独配置不提供 initial pose 的协议和官方 regression checkpoint。
7. 增加 mmap 和本地物化；实测网络盘约 0.15 it/s，本地约 1.03 it/s。

### R — Result

| 数据/协议 | Validation | Test | Test Subject | Test Device |
|---|---:|---:|---:|---:|
| v0.1 tracking，GT-seeded | 11.09° | 13.02° | 13.76° | 12.88° |
| v0.1 regression，纯 EMG | 17.22° | 19.48° | 21.11° | 19.19° |
| v1.0 regression，纯 EMG | 17.71° | 16.54° | 19.83° | 14.73° |

- 明确 tracking 与 regression 差距来自任务合同，不再将 GT-seeded 结果当作公开 regression 榜单表现。
- v1.0 regression 在 test/泛化轴上较上一版本改善约 2–4°，支持“增加干净训练数据改善泛化”的判断。
- 建立了可复用的脚本、配置、split 和报告体系。

### 业务价值

把“模型跑得更低”转化为“在同一协议上可比较”，避免因初始状态、GT 来源或聚合方式不同造成错误技术决策。

## 3.4 项目四：SHM 标准手数据与单人模型训练闭环

### S — Situation

标准手数据来自多个上游：clean EMG、Manus skeleton、SHM retarget、pool.db 质量门禁和新增抓握数据。早期训练常缺少统一 split、完整产物索引和 ONNX 验收，容易出现“模型训练完成但无法复现”或“test 指标存在泄漏仍被误用”的情况。

### T — Task

把 SHM-calibrated 数据转换为标准 EMG2Pose 训练输入，并形成从数据、训练、评估、checkpoint 到 ONNX 和报告的完整闭环。

### A — Action

1. 建立 SHM-calibrated dataset 构建脚本，将 Manus skeleton retarget 成标准手 joint angles。
2. 将 clean EMG 与 SHM theta 按时间对齐，生成包含 emg 和 joint_angles 的训练 NPZ。
3. 支持 prebuilt 模式，跳过不必要的重复清洗。
4. 固化 Hydra 配置、split、warm-start、strict checkpoint 和 mmap。
5. 训练后统一输出 best/last checkpoint、metrics、曲线、test 结果和两个 ONNX 文件。
6. 为每个单人实验记录数据来源、质量门禁、切分、训练命令、指标和风险。
7. 编写 single-subject overfit SOP，形成数据→模型→部署问题定位顺序。

### R — Result

| 实验 | 任务 | Test MAE | 交付 | 结论边界 |
|---|---|---:|---|---|
| lql-0125 right + grip | tracking warm-start | 4.187° | checkpoint + 两段式 ONNX | 旧数据含 36 条 pool.db failed，占约 4%–5% 帧，需 passed-only 对照 |
| tyq-0920 right | regression warm-start | 6.740° | checkpoint + 两段式 ONNX | test 仅 2 条且与 val 重叠，只作链路参考 |
| lsh-0126 left + grip | tracking warm-start | 8.297° | checkpoint + 两段式 ONNX | 相比旧结果变差，用于暴露数据/切分/补充动作影响 |

- 完成训练、评估、checkpoint 和 ONNX 产物闭环。
- 不只报告最好指标，也将 split 泄漏、failed 样本混入和 test 规模不足写入报告。
- 形成可复用的单人训练模板和问题排查 SOP。

### 业务价值

将标准手训练从“个人机器上的一次实验”转化为可以交接和复核的模型生产记录，同时建立对指标可信度的硬约束。

## 3.5 项目五：Benchmark v2 通用训练 Pipeline 与 S3 稳定性治理

### S — Situation

Benchmark v2 pose main track 包含 34,163 个样本，训练需要三 seed、50,000 steps。数据位于 S3/s3fs，共享缓存退化时出现 ZIP header 短读、EIO、全零稀疏缓存和挂载目录消失。直接反复启动训练既浪费 GPU，也无法判断是对象损坏、DataLoader 并发还是挂载问题。

### T — Task

建立一个可审计、可恢复、可排队的大规模训练入口，并定位共享存储失败的真实层级。

### A — Action

1. 将数据准备、真实 batch 预检、单 seed 训练、GPU 排队和状态查询拆成独立模块。
2. 统一 MainExp 与 existing recipe 的 data_stage/metadata.csv 合同。
3. 增加 sample path、长度索引、schema、finite 和 split×stage 代表样本检查。
4. 增加代码快照、run_info、配置冻结、best/last checkpoint 和多 seed 目录。
5. 逐步降低变量：减少初始化并发、lazy session、num_workers=0、单进程重试。
6. 扫描全部 34,163 个对象的 ZIP magic，定位失败发生在 s3fs/FUSE 层。
7. 设计 boto3 Range GET 直连方式，只读取 ZIP/NPY header 和训练窗口，避免全文件落入 s3fs cache。

### R — Result

- 正式 split：train 28,908、val 2,745、test 2,510，共 34,163。
- 48 个 split×stage 代表文件通过 schema/finite 检查，316 个版本组合通过 header 检查。
- CPU Lightning smoke 完成 train/val/test，Benchmark 相关测试 40 passed。
- 诊断出挂载退化时仅 864/34,163 文件头可读；证据指向 s3fs 缓存/挂载，不支持“源对象全部损坏”的判断。
- 三 seed 后续训练均到约 20,349 steps：

| Seed | 最佳 val step | 阶段性 val MAE |
|---:|---:|---:|
| 42 | 20,000 | 9.282° |
| 43 | 15,000 | 10.579° |
| 44 | 18,000 | 10.532° |
| 均值±标准差 | — | 10.131±0.600° |

- 三个进程最终因 DataLoader worker SIGTERM 退出，未达到 50,000 steps，也没有正式 test MAE；因此结果被正确标为“阶段性”，未包装成 Benchmark v2 正式成绩。

### 业务价值

建立了大规模训练的故障隔离和停止规则：先证明数据可读、真实 batch 可训练，再占用 GPU；出现基础设施确定性失败时停止盲目重启并保留证据。

## 3.6 项目六：Vision 标签训练价值与 Manus 真值审计

### T — Task

### A — Action

2. 汇总 MCAP topic、消息数、时长、采样率和文件哈希。

4. 划分 EMG+Manus 候选与 EMG+Image+Manus 强配对候选。
5. 检查 subject_id、日期分区、全零关节、大跳变和 manifest/raw 映射。

## 3.7 项目七：Chord Fusion2Pose 三模态双手架构

### S — Situation

目标是从双目视频、双侧 sEMG 和双腕 IMU 预测双手 SHM 姿态。三种模态采样率不同、时间不对齐、存在缺帧；原始两张架构图只表达概念，没有完整代码合同、有效性规则、Root 物理输出、训练/评估入口和数据限制说明。

### T — Task

严格复现并比较两套架构：

1. Pose-State Query：以状态为中心，用三路证据做逐 DoF 更新；
2. Chord-MulT：六个有向 cross-attention 后做全局融合。

同时完成从 raw/video/label 到训练、反向、checkpoint、评估、NPZ 和文档的全链路。

### A — Action

#### A1. 输入与数据合同

- 固定 bilateral EMG 为 left16+right16，IMU 为 left wrist9+right wrist9。
- 以 int64 sync_ts_ns 作为共同物理时钟。
- 建立 raw、video、SHM 自动配对、skipped reason、视频首中末帧检查和 subject-level split。
- 当前 20h 清洗集整理为 368 个视频、约 23.6 小时、约 253 万帧。
- 对缺失模态采用零值+全 false mask，而不是伪造有效观测。

#### A2. Encoder 与异步因果对齐

- Vision：Light-CNN、MobileViT、Swin 可切换。
- sEMG：causal TCN、Production TDS、TDS+TCN 可切换。
- IMU：因果 TCN。
- Cross-Attention 只允许 source_ts≤target_ts 且位于历史窗口。
- Production TDS 精确推导：2000 raw samples→3 tokens，总 stride 80 samples/40 ms，left context 1790 samples/895 ms。

#### A3. Pose-State Query

- 三路独立 causal Memory Bank。
- 由上一 SHM23、速度、IMU 和 Δt 形成 X⁻(t)。
- 7 个 Pose Query 查询 Visual/Geometry、IMU、EMG memory。
- 每路输出 23D innovation、gain、log variance。
- IMU learned update 只允许 wrist DoF 21:23；EMG 只允许 finger DoF 0:21。
- QGR-PU 逐 DoF 更新，EMG 缺失时 exact fallback。
- 窗口内 carry 不 detach，支持 BPTT。

#### A4. Chord-MulT

- 完成 IMU→Image、EMG→Image、Image→IMU、EMG→IMU、Image→EMG、IMU→EMG 六条独立有向边。
- 每个 target 拼接两路 context 成 512D memory。
- 三路 endpoint 形成 3×512=1536D global feature。
- LayerNorm+Residual MLP 输出 bilateral Pose52。
- 支持 edge hard ablation 和 branch modality dropout。

#### A5. Loss 与结构化输出

- Pose-State 使用 center、sequence、heteroscedastic NLL、dynamics、velocity 五项 masked loss。
- Chord 当前以有效 theta20 的 masked Smooth-L1 为主，避免在无 Root6 GT 上制造伪监督。
- 实现 SHM23 joint limits、可微 FK、SHM25、Root、SO(3) 检查。
- 实现 frame_index、hand_side、theta23、theta_valid、SHM25、wrist rotation、wrist valid、accepted 的正式 prediction.npz writer。

#### A6. 训练性能

- 定位 H200 利用率接近 0 的主要原因不是模型，而是每个 window 重开 MP4 并随机 seek H.264。
- 实现 MP4 一次顺序解码和 FP16 Vision Feature Cache。
- 缓存 shape 为 [T,2,256]，保留 frame validity 和 int64 timestamp。
- 训练阶段跳过重复视频解码，EMG/IMU 仍按真实时间做因果窗口。

#### A7. 代码审计与关键修复

- 修复 geometry 分支未定义 config。
- 修复标签 searchsorted 选到未来样本。
- 修复最新无效 sample 覆盖更早合法 causal sample。
- 修复 Chord 全空 attention row 导致 SoftmaxBackward NaN。
- 修复 memory padding/bias 产生伪 evidence。
- 修复 Pose-State 窗口内 X(t-1)→X⁻(t) 未真正闭环。
- 修复 Root frame 命名导致 wrist DoF 可能重复施加。
- 增加 SO(3) 正交与 det=+1 验证。
- 修复 CUDA 未显式 AMP 仍开启 autocast。
- 修复训练结束评估 last 而不是 best checkpoint。
- 修复多 session NPZ 主键冲突。
- 修复 rejected Root NaN 进入 streaming cache。
- 修复半精度下 int64 ns 时间差溢出风险。

### R — Result

#### 软件闭环

- 两套架构均完成 raw→encoder→memory/attention→head→loss→backward→checkpoint→resume→eval。
- 双手输入与双手输出合同已实现；未标注侧使用 mask，不以零角冒充 GT。
- 完成 90+ 项单元、合同和集成测试，以及真实 MP4+NPZ forward/backward smoke。
- 形成代码模块说明、架构审计、逐层张量推导、流程图、PPT 和 GitLab 协作文档。

#### 20h 实验结果

| 模型 | Best epoch | Overall MAE | Left MAE | Right MAE |
|---|---:|---:|---:|---:|
| Pose-State Query | 14 | 22.62° | 28.26° | 21.53° |
| Chord-MulT | 16 | 25.40° | 35.20° | 23.51° |

- Pose-State Query 比 Chord-MulT 低约 2.78°。
- 关闭 early stopping 后，Pose-State 相对第一轮改善约 1.44°；Chord 未产生新的 best。
- 两模型均在 best epoch 后出现训练 loss 继续下降、val loss 不再改善的过拟合趋势。

#### 结论边界

- 当前 test 有效角元素左手 960、右手 4,960，Overall 更接近右手，不是左右手等权指标。
- 当前主要监督 theta20；theta23 中 index 2 和 wrist 21:23 缺少直接 GT。
- 当前真实数据缺少可信 camera Root/geometry/head IMU，因此不能报告正式 SHM25 MPJPE。
- Pose-State 可按正式 prediction.npz 合同导出，但无 Root 时 accepted=false 是正确行为。
- Chord bilateral 当前原生输出 prediction_pose52.npz；Pose52 中 root6 是全局刚体位姿，不能替代 theta23 wrist articulation。正式 prediction.npz 仍需完整 theta23 与 Root 监督。

### 业务价值

建立了一个可对比两种融合思想、可进行模态/encoder/edge/loss 消融、并对物理输出有效性负责的多模态研究平台。更重要的是，明确区分了“软件链路完成”和“标签支持的物理精度完成”。

## 4. 跨项目问题—解决方案矩阵

| 共性问题 | 典型表现 | 解决方案 | 沉淀能力 |
|---|---|---|---|
| 多传感器时间错位 | EMG 比 Manus 晚约 1 s；异步采样 | 共同 int64 时间轴、重叠裁剪、严格因果 mask | 时间同步与因果建模 |
| 数据格式漂移 | timestamp 两种时钟域、字段长度不一致 | schema 探测、fallback、skip reason、版本化合同 | 数据鲁棒性 |
| 标签口径混乱 | ergo/skel、tracking/regression 混比 | 强控制 A/B、协议分离、统一指标 | 实验可辨识性 |
| 被试泄漏 | session 随机切分导致同人跨 split | subject-level split 和自动交集检查 | 泛化评测 |
| 大规模 I/O | NFS mmap 慢、s3fs EIO、H.264 随机 seek | 本地物化、S3 Range GET、顺序解码、feature cache | 训练基础设施 |
| 无效值伪证据 | 零填充被网络 bias 利用 | value+hard mask 双合同、全空 row 安全 softmax | 数值稳定性 |
| 双手监督不完整 | 输入双手但每条只标一手 | 始终预测双手，loss 只打开真实标签侧 | Masked learning |
| 物理坐标混淆 | wrist articulation 与 root6 混用 | SHM23/FK/Root/SHM25 分层合同 | 运动学可解释性 |
| 指标不可复现 | last checkpoint、不同聚合口径 | best reload、配置快照、统一 evaluator | 可复现训练 |
| 实验边界不清 | 阶段结果被当成量产精度 | formal/staged/blocked 分级和证据索引 | 技术判断与风险管理 |

## 8. 质量保障与可审计性

### 8.1 代码与合同

- 使用 Ruff、compileall、pytest 对 Chord 代码进行静态、语法和行为回归。
- 对 timestamp 使用 int64 先做差，再转 float 秒，避免 AMP 下绝对纳秒值溢出。
- 对所有 missing modality 使用 hard valid mask，防止零填充和 bias 形成伪证据。
- 对 checkpoint 版本、严格加载、best reload 和 legacy 模式做显式约束。
- 对 NPZ shape、主键唯一性、有限性、SO(3) 和 accepted 条件做 writer 级校验。

### 8.2 实验与指标

- 区分 training loss、rad MAE、degree MAE、per-session 与 per-frame。
- 区分 regression 与 tracking、正式 test 与阶段性 val、完整标签与 masked 标签。
- 对左右手、每个 DoF、有效元素数量和数据不平衡进行单独记录。
- 对无法形成正式结论的实验明确说明，不用 smoke 或中间 checkpoint 替代正式结果。

### 8.3 数据

- 对失败样本保留 skipped manifest 和 skip_reason。
- 使用 subject-level split 防止跨 session 泄漏。
- 对时间逆序、未来读取、NaN/Inf、坏旋转矩阵和损坏文件做硬拒绝。
- 不将不存在的 Root、另一只手标签或缺失的 SHM DoF 以零值冒充真值。

## 13. 最终总结

本阶段工作的核心不是完成若干孤立模型，而是建立了一套从数据到结果的可信链路：

~~~text
原始传感器
  -> 时间与质量审计
  -> 可复现数据合同与 split
  -> 单模态/多模态 encoder
  -> 因果融合与状态更新
  -> SHM 物理输出
  -> masked loss 与有限反向
  -> checkpoint / ONNX / NPZ
  -> 统一评测与结论边界
~~~

已经解决的问题包括：秒级时间错位、GT 和任务协议混比、大规模 I/O、右手符号错误、全空 attention NaN、无效模态伪证据、双手单侧监督、Root 坐标混淆和实验不可复现。

尚未解决的问题也已经被明确量化：完整双手 SHM23/Root 标签、Benchmark v2 正式 test、Vision processed 标签和 force2 标签语义。下一阶段可以围绕这些真实瓶颈推进，而不再重复消耗时间在已经闭环的基础设施和概念验证上。
